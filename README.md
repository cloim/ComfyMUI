# ComfyMUI

모바일에서 사용하는 ComfyUI 이미지 작업실입니다. React, TypeScript와 Tailwind CSS로 구현한 설치형 PWA입니다.

## 실행

Node.js 24 LTS를 사용합니다.

```sh
npm ci
npm run dev
```

개발 화면은 `http://localhost:5173`입니다. ComfyUI를 기본 포트 8188에서 실행한 후 앱의 연결 설정에서 `/comfy`로 연결하세요.

빌드 결과를 실행하려면 다음 명령을 사용합니다.

```sh
npm run build
npm start
```

실행 주소는 `http://localhost:4173`입니다. 앱 서버는 기본적으로 `0.0.0.0`에서 수신합니다. 같은 LAN의 모바일에서는 PC의 LAN IP와 4173 포트로 열 수 있습니다. 로컬 테스트용으로 신뢰할 수 있는 네트워크에서 사용하세요. 외부 공개와 인증 구성은 별도 배포 작업입니다.

서버 환경변수:

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `COMFY_URL` | `http://127.0.0.1:8188` | 고정 ComfyUI 백엔드 주소 |
| `PORT` | `4173` | 빌드 실행 서버 포트 |
| `HOST` | `0.0.0.0` | 수신 인터페이스 |

PowerShell 예: `$env:COMFY_URL='http://127.0.0.1:8188'; npm start`

### Docker Compose 실행

Docker Compose를 사용하면 ComfyUI GPU 서비스와 ComfyMUI Node.js 서비스를 컨테이너 환경으로 분리하여 안전하게 실행할 수 있습니다.

- **Named Volume (2개)**:
  - `comfy-data`: ComfyUI 영속 데이터 (`models/`, `output/`, `input/`, `user/`, `temp/`)
  - `comfymui-data`: ComfyMUI 영속 데이터 (SQLite DB 및 썸네일 캐시)
- **로컬 모델 연결**: 호스트의 기존 모델 폴더(`HOST_MODELS_DIR`, 기본값: `E:/Models`)를 읽기·쓰기 bind mount로 연결하며, `extra_model_paths.yaml`을 통해 `comfy-data/models`와 함께 검색합니다. 신규 모델 다운로드는 `comfy-data/models`에 기본 저장됩니다. 모델과 LoRA의 CivitAI 다운로드에서 저장 위치를 Docker 볼륨 또는 로컬 모델 폴더로 선택할 수 있으며, 자동 분류는 선택한 저장 위치 아래에 적용됩니다.
- **출력 폴더 공유**: `comfy-data` 볼륨이 ComfyMUI에도 공유되어 갤러리 조회와 이미지 삭제 쓰기 권한이 유지됩니다.

#### 1. 환경 설정

`.env.example`을 복사하여 `.env`를 생성하고 필요한 경로와 포트를 조정합니다:

```sh
cp .env.example .env
```

주요 설정값:
- `HOST_MODELS_DIR`: 기존 로컬 Windows 모델 폴더 경로 (기본값: `E:/Models`)
- `COMFY_PORT`: 호스트 ComfyUI 포트 (기본값: `8188`)
- `PORT`: 호스트 ComfyMUI 앱 포트 (기본값: `4173`)
- `COMFY_EXTRA_ARGS`: ComfyUI 시작 추가 옵션 (기본값: `--lowvram --reserve-vram 1`)

#### 2. 데이터 이전 (비파괴적)

기존 로컬의 SQLite 설정 DB와 출력 이미지를 Docker 볼륨으로 안전하게 이전합니다. 원본 파일은 그대로 보존됩니다:

```sh
node scripts/migrate-data.mjs
```

이 스크립트는 SQLite WAL 체크포인트를 수행한 후 `data/backups/`에 타임스탬프 백업을 남기고 `comfymui-data` 및 `comfy-data` 볼륨으로 복사합니다.

#### 3. 서비스 빌드 및 기동

```sh
# 이미지 빌드
docker compose build

# 서비스 백그라운드 기동
docker compose up -d

# 실행 상태 및 로그 확인
docker compose ps
docker compose logs -f
```

기동 후 브라우저에서 `http://localhost:4173`으로 접속할 수 있습니다.

#### 4. 서비스 종료

```sh
docker compose down
```
*(주의: `docker compose down -v`나 Docker 시스템 prune 등 볼륨 삭제 옵션은 사용하지 마세요.)*


## 사용 흐름

1. 연결 설정에서 서버 주소를 저장하고 연결을 확인합니다. 미리보기 모드는 샘플 일러스트로 UI만 체험합니다. 실제 GPU 작업을 요청하지 않습니다.
2. Flux1.d, krea2, moss, qwen 2.1 중 계열을 고르고 모델을 선택합니다. 계열에 맞는 인코더, VAE와 기본 생성 설정을 자동으로 준비합니다. 프롬프트와 비율을 정한 뒤 이미지 생성을 누르세요. JSON 파일을 가져올 필요가 없습니다. 해당 계열의 LoRA만 선택 목록에 표시하며 Flux1.d는 모델/CLIP 강도, 나머지 계열은 모델 강도를 조절합니다.
3. 고급 설정에서 해상도, Seed와 무작위 생성, steps, CFG, sampler, scheduler, denoise를 조절합니다. Flux.1 구성은 CLIP L, T5, VAE와 guidance를 지원합니다.
4. 이미지 생성 후 실시간 진행과 결과를 확인합니다. WebSocket 재접속 중에도 HTTP 폴링으로 기록과 큐를 확인합니다. 실행 중인 작업은 계속 추적하며, 대기 취소는 해당 prompt ID만 삭제합니다. 서버 전역 interrupt를 호출하지 않습니다.
5. 기록에서 상세 이미지, 배치 결과, 저장과 설정 재사용을 사용합니다. 같은 PC의 앱 서버는 ComfyUI output 폴더의 이미지와 PNG 생성 정보를 최대 5,000개까지 읽습니다. 기록에서 파일을 삭제하면 원본 파일도 삭제됩니다. 미리보기·직접 연결에서는 기기 내 기록을 사용하며 최근 500개 작업을 IndexedDB에도 보관합니다. ComfyUI의 전체 `/history`를 조회하거나 삭제하지 않습니다.
6. 상단 저장 버튼으로 현재 설정을 프리셋에 저장합니다. 프리셋에서 상세 보기, 적용, 이름과 설명 수정, 현재 설정으로 교체, 복제, 삭제와 JSON 가져오기/내보내기를 사용합니다. 가져오기는 항상 새 항목을 추가합니다. 최대 100개를 보관합니다.

## 시안, 실험과 모바일 사용

- **빠른 시안 → 최종 생성:** 만들기의 빠른 시안에서 해상도·Steps 변경을 확인한 뒤 한 장을 생성합니다. 시안 결과의 `이 시안으로 최종 생성`은 원래 해상도와 Steps를 복원하고 실제 Seed·프롬프트·LoRA를 유지합니다. 두 단계 모두 실행 전에 설정을 확인합니다. 모델에 따라 시안 품질이 다르며, 해상도를 바꾸면 같은 Seed여도 구도가 달라질 수 있습니다. API 워크플로와 업스케일은 대상에서 제외합니다.
- **조건별 실험:** Steps, CFG 또는 선택한 LoRA의 모델 강도 한 가지를 2~6개 값으로 비교합니다. 모든 조건에 같은 Seed를 사용하고 실행 전 장수와 조건을 보여줍니다. 기록의 실험 묶음 필터와 조건 라벨에서 결과를 찾고 기존 비교 뷰어로 비교할 수 있습니다.
- **오류 복구:** 메모리 부족은 변경될 해상도·배치 수를 확인하고 재시도합니다. 모델 오류는 설치 목록을, 연결 오류는 연결 설정을 확인합니다. 제출 응답을 잃거나 전송 중 새로고침한 요청은 `서버 작업 확인`으로 기존 큐와 같은 서버의 저장 결과를 먼저 찾습니다. 확인되지 않은 요청을 다시 보낼 때는 중복 생성 가능성을 안내합니다.
- **진행과 예상 시간:** 서버 대기, 모델 준비, 샘플링, 이미지 변환·저장을 구분합니다. 같은 서버·모델·샘플러 등의 최근 완료 기록을 바탕으로 배치·해상도·Steps를 반영한 시간 범위와 표본 수를 표시합니다. 대기 시간은 생성 시간에 포함하지 않으며 다른 앱의 작업은 대기 건수에서 제외됩니다. 가져온 워크플로·업스케일과 표본이 부족한 경우에는 예상 시간을 표시하지 않습니다.
- **절전:** 설정의 `앱 및 알림`에서 조절합니다. 기본 절전 모드는 화면 유지와 백그라운드 오디오를 사용하지 않으며 미리보기·백그라운드 확인 빈도를 낮춥니다. 절전을 끄면 두 기능을 개별 선택할 수 있습니다. 느린 통신에서도 미리보기 빈도를 줄입니다. 서버에 접수된 작업은 앱을 닫아도 실행되지만 앱이 종료되면 완료 알림은 전달되지 않을 수 있습니다.

갤러리는 파일 변경 감시로 인덱스를 갱신하고 주기적으로 전체 대사를 수행합니다. 감시를 지원하지 않으면 짧은 TTL로 갱신하며 수동 새로고침은 즉시 전체 대사합니다. 80개를 넘는 목록은 보이는 행 위주로 렌더링하며 검색·필터·스크롤 위치를 같은 탭에서 복원합니다. 생성 진행 중 기록 저장은 최대 초당 한 번으로 묶고 제출·완료·오류 등 상태 변경과 화면을 떠나는 시점에는 즉시 저장합니다. 설정 폼은 진행률과 별도로 구독합니다.

## 기기 간 설정과 충돌 복구

생성 설정·프리셋·모델 분류 등 공유 설정은 앱 서버의 SQLite(`data/comfymui.db`)에 저장하고 기기에 사본을 둡니다. 서버는 버전을 비교해 오래된 기기의 쓰기를 거부합니다. 다른 기기와 변경이 겹치면 양쪽 값을 기기에 보관하고 `변경 비교`에서 이 기기 초안 또는 서버 설정을 선택합니다. 서로 다른 프리셋 항목의 변경은 자동 병합하며 같은 항목의 변경이나 삭제 충돌은 선택을 요청합니다.

설정 → 앱 및 알림 → `동기화와 보관 초안`에서 최근 20개 충돌의 양쪽 버전을 복원할 수 있습니다. 보관 초안은 해당 브라우저에만 남으므로 브라우저 데이터 삭제 전에는 프리셋을 내보내세요. 기존 DB는 값을 유지한 채 revision 컬럼을 자동 추가합니다. `/api/state` 쓰기는 각 키의 `revisions`가 필요하며 누락하면 428, 충돌은 409와 현재 서버 값을 반환합니다. 서버와 프런트엔드를 함께 갱신하세요.

## 모델과 API 워크플로

모델 목록은 `CheckpointLoaderSimple`, `UNETLoader`, `UnetLoaderGGUF`와 대체 GGUF 로더의 설치값을 합칩니다. 같은 파일이 여러 로더에 나와도 한 번만 표시하며 원래 파일명과 로더를 함께 저장합니다. 설치 목록 새로고침으로 서버의 변경 사항을 다시 읽을 수 있습니다.

모델 본체의 통합 보관 위치는 `ComfyUI/models/diffusion_models/<계열>/`를 권장합니다. 앱의 모델 다운로드는 서버가 제공한 `diffusion_models` 경로를 우선 선택합니다. 기존 체크포인트 워크플로도 사용하려면 서버의 `extra_model_paths.yaml`에서 `checkpoints` 검색 경로에 이 폴더를 추가하세요. 텍스트 인코더, VAE와 LoRA는 각 전용 폴더에서 관리합니다.

지원 계열은 **Flux1.d, krea2, moss, qwen 2.1 네 가지**입니다. 모델 목록에는 이 네 계열의 텍스트 이미지 생성 모델을 표시합니다. 참조 이미지가 필요한 Kontext/편집 모델, 영상 모델과 별도 Nunchaku 구성이 필요한 모델은 기본 목록에서 제외합니다. 기존의 다른 계열 설정은 프롬프트를 보존하며 지원 계열로 정리합니다.

계열별 자동 구성:

| 계열 | 텍스트 인코더 | VAE | 기본 Steps / CFG |
| --- | --- | --- | --- |
| Flux1.d | CLIP L + T5 XXL | Flux AE | 24 / 1, guidance 3.5 |
| krea2 | Qwen3-VL 4B, krea2 타입 | Qwen Image VAE | 8 / 1 |
| moss | Qwen3.5 9B, moss_image 타입 | Flux2 VAE | 24 / 4 |
| qwen 2.1 | Qwen3-VL 8B, qwen_image 타입 | Qwen Image 2.1 VAE | 28 / 4 |

Krea2는 해상도에 맞는 Flux 샘플링 설정을 연결하고, MOSS와 Qwen 2.1은 공간 축소율 16의 잠재 이미지를 사용합니다. ComfyUI가 빈 잠재 이미지의 채널을 모델에 맞게 조정하며, 요청한 가로/세로와 배치 수를 유지합니다. Qwen 2.1은 전용 텍스트 인코딩 노드에서 긍정/부정 프롬프트를 함께 처리합니다. Flux1.d와 krea2의 해상도는 16의 배수, moss와 qwen 2.1은 32의 배수로 입력하세요.

LoRA도 네 계열에 맞게 분류합니다. 이전 Qwen Image의 LoRA는 Qwen 2.1 목록에 자동으로 섞지 않습니다. 모델 카드의 분류 버튼에서 호환성을 확인한 파일을 직접 지정할 수 있으며 분류 정보는 이 기기에 저장됩니다. 계열 변경 시 다른 계열 LoRA를 해제합니다. Krea2, MOSS와 Qwen 2.1은 모델 전용 LoRA 노드를 사용합니다. GGUF 인코더를 선택하면 GGUF 전용 CLIP 로더를 연결합니다.

GGUF를 사용하려면 서버에 ComfyUI-GGUF 등 호환 로더와 해당 파일이 있어야 합니다. 보통 diffusion GGUF는 `models/diffusion_models` 또는 `models/unet`, 텍스트 인코더 GGUF는 `models/text_encoders` 또는 `models/clip`에 둡니다. 앱은 설치나 모델 다운로드를 수행하지 않습니다. 서버가 반환하는 GGUF 파일이 없으면 목록에 0개와 설치 안내를 표시합니다. GGUF는 저장 형식이며 모든 계열에 공통으로 호환되는 모델 종류가 아닙니다.

일반 생성에서는 아래 고급 도구가 필요하지 않습니다. 생성 그래프를 별도로 점검하거나 수정할 때는 ComfyUI의 **API 형식 JSON**을 사용할 수 있습니다. 일반 편집기 JSON(`nodes`, `links`)은 지원하지 않습니다.

- 고급 설정의 API 워크플로 탭에서 JSON을 가져옵니다. 최대 2MB와 500개 노드를 허용합니다.
- 가져온 그래프의 연결을 유지하며 문자열, 숫자, 불리언과 서버 스키마의 선택 입력을 편집합니다.
- 가져온 그래프가 활성화되면 기본 생성 설정은 잠깁니다. Seed를 포함한 그래프 내 값만 실행합니다.
- 서버에 없는 노드와 설치값, 필수 입력과 숫자 범위를 확인합니다. 서버의 최종 검증 오류는 작업 상세에 표시합니다.
- 이미지 결과는 노드의 `images` 출력을 수집합니다. 파일 업로드, 마스크 편집과 영상/오디오 결과 재생은 현재 UI 범위에 포함되지 않습니다. 복합 입력은 원본 JSON을 수정한 뒤 다시 가져옵니다.
- 그래프를 내보낸 후 기본 생성으로 돌아갈 수 있습니다. 워크플로도 프리셋과 생성 기록에 함께 저장합니다.

## 연결 구조

기본 `/comfy` 경로는 앱 서버가 고정 백엔드로 전달합니다. 개발 서버와 빌드 서버 모두 HTTP와 WebSocket을 프록시합니다. 외부 Origin을 거부한 후 ComfyUI의 Host/Origin 검사에 맞게 전달하므로, ComfyUI에서 CORS를 전체 허용할 필요가 없습니다. 임의의 URL을 받는 범용 프록시는 제공하지 않습니다.

연결 확인은 가벼운 `/queue` 실시간 응답과 사용 가능한 노드 정보를 함께 확인합니다. 이전 노드 정보가 있으면 IndexedDB에서 즉시 복원하고 최신 정보는 병렬로 갱신합니다. 캐시만으로 연결 성공을 표시하지 않습니다. `/comfy/object_info`는 모든 노드의 입력·출력 스키마를 유지하며 편집기 설명을 제외하고 gzip으로 전달합니다. 지원 브라우저는 `?packed=1`의 gzip 본문을 직접 해제해 중간 프록시의 HTTP 압축 해제에도 작은 전송량을 유지합니다. 앱 서버는 시작할 때 노드 정보를 미리 준비하고 동시 조회를 하나로 합칩니다. 30초가 지나면 이전 결과를 즉시 전달하며 백그라운드에서 갱신합니다. 설치 목록 새로고침은 이 캐시를 건너뛰어 최신 조회를 기다립니다. 화면 복귀나 목록 갱신 시 정상 WebSocket은 유지하며, 주소 변경·미리보기 전환 시에는 이전 조회를 취소합니다. 직접 주소의 GET 요청은 불필요한 CORS 사전 요청을 발생시키지 않습니다.

직접 주소를 연결할 때는 ComfyUI에서 앱 Origin의 CORS를 허용해야 합니다. HTTPS 프런트엔드에서 HTTP 백엔드에 직접 연결하면 혼합 콘텐츠 제한이 있으므로 `/comfy` 또는 HTTPS 백엔드를 사용하세요. 모바일에서 `localhost`는 모바일 기기 자신을 가리킵니다. PC 백엔드에는 `/comfy` 연결을 권장합니다.

## PWA와 로컬 데이터

홈 화면 설치와 서비스워커는 HTTPS 또는 `localhost`에서 동작합니다. LAN의 일반 HTTP 주소에서는 화면과 생성 기능을 사용할 수 있으며 설치와 오프라인 기능에는 HTTPS가 필요합니다. Safari는 공유 메뉴의 홈 화면에 추가를 사용합니다. 새 서비스워커가 대기하면 업데이트 버튼을 제공합니다.

서비스워커는 번들, 폰트, 아이콘, 명시된 샘플과 최대 150개의 썸네일을 캐시합니다. ComfyUI API와 생성 이미지 원본은 캐시하지 않습니다. 공유 설정은 서버 DB와 기기의 localStorage 사본에, 작업 스냅샷은 localStorage와 IndexedDB에 저장합니다. 브라우저 데이터를 삭제하면 기기 내 기록과 보관 초안도 삭제됩니다. 중요한 설정은 프리셋 JSON으로 내보내세요. 오프라인에서도 저장된 설정과 프리셋을 편집할 수 있습니다. 실제 이미지 생성에는 연결이 필요합니다.

## 검증

```sh
npm test
npm run build
npm run test:e2e
```

실제 GPU의 네 계열 검사는 기본 테스트와 분리했습니다. 서버가 대기 중일 때만 실행하며 각 계열의 설치 모델로 256×256, 4 steps 이미지를 한 장씩 요청합니다. PNG 크기까지 확인하고 `docs/real-four/`에 요청/결과를 보관합니다.

```sh
npm run test:real
```

단위 테스트는 그래프와 LoRA 연결, Flux 구성, 잘못된 입력과 프리셋 스냅샷을 검증합니다. 통합 테스트는 4174와 8799 포트의 격리된 프로토콜 서버를 자동 실행하고 종료합니다. 실제 GPU 서버와 분리되며 생성, 배치, 오류와 취소, 프리셋, 워크플로, 오프라인 PWA와 325/390/1440px 화면을 확인합니다. Windows Chrome 경로는 `playwright.config.ts`에서 설정합니다.

실제 서버가 대기 중이고 이 프로젝트 앱 서버가 실행 중일 때만 다음 검사를 실행합니다. 검증 스크립트는 지정된 Flux.1 diffusion 모델이 설치된 로컬 환경 전용입니다. 작은 풍경 한 장을 실제로 요청하며 요청, 결과와 화면 증거를 무시 경로 `docs/`에 저장합니다.

```sh
node scripts/verify-real.mjs
```

아이콘을 수정할 때 SVG와 `scripts/build-icons.py`의 도형을 함께 갱신한 뒤 실행합니다.

```sh
uv run --with pillow python scripts/build-icons.py
```

공용 Modal과 SelectControl의 프로젝트 적용은 기존 공용 컴포넌트 규격을 따릅니다. 화면은 독립적으로 설계했으며 외부 브랜드 디자인 토큰을 복사하지 않았습니다.
